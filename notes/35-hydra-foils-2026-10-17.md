## 0. Question

T2 (`notes/33`, `Antihydra/Foils.lean`) showed for Antihydra that halting members of the
rounding-choice family accumulate at the cryptid, so no rounding-blind argument decides it.
`Census.lean` writes Antihydra, int-y1 #323, BB(2,5) Hydra, BBf #218 and Bigfoot in int-y1's
`Hydra` schema: `x ↦ p⌊x/q⌋ + g[x mod q]`, walk `y ↦ y + w[x mod q]`, cryptid "`y ≥ 0`
forever".  T3 lifts the T2 gate to the schema.

**The family** (`Sys`, `Sys.step`).  A defect-`d` member adds `τ x ∈ {0, …, d}` to the image,
walk unchanged.  The block subfamily `F_{L,d}` (`member q L σ`) has `τ` constant on blocks of `qL`
consecutive integers (`blk q L x = x / (qL)`).  **[Lean]** `Sys.step_zero`: the all-zero member
is int-y1's `hydraIterate`; `Sys.hydra_iff`: `Hydra p q g w s ↔` the all-zero member never halts.
Instances `antihydra_iff`, `hydra323_iff`, `hydraBB25_iff`, `hydra218_iff`, `bigfoot_iff` (the
last through `Dyn.nonhalt_iff_hydra`, so it is Bigfoot's own `Dyn.orbit`).

## 2. The host analysis, checked

- *`realize` and block uniqueness use only expansion.*  Confirmed **[Lean]**: `Sys.realize` takes
  only the gap hypothesis, and `Sys.exists_gap` supplies it from `q < p` (with the bound
  `M = q(B + q + |W|)`, `B` bounding `−g`).
- *`q = 2` steering is the window condition with `d = 1`.*  Confirmed: `Sys.window_two` + row 4;
  the `q = 2` gate is a corollary of the general one, not a separate argument.
- *Sufficient condition for `q ≥ 3`.*  Confirmed as row 4, and strengthened twice: (a) windows only
  need to start at images of *reachable* residues (row 6), (b) the trap need not be all-negative:
  any trap with a potential that falls by one per step drains the walk (row 3).  (b) is what
  matters for Bigfoot: `14 → 13 → 7`.
- *Bigfoot's `d_min = 14`.*  Confirmed for the plain window (`bigfoot_window`).  The reachable
  set is exactly the 18 residues `≢ 0 (mod 4)` (invariant **[Lean]**, all attained **[computed]**);
  it lowers the window to `13`.

**Why the digit matters.**  `x mod q` alone does not fix the next window: `p⌊x/q⌋ mod q` depends on
`t = ⌊x/q⌋ mod q`.  The certificates of rows 6, 10, 11 quantify over `t` adversarially.  For
`q = 2, 3` with `p ≡ 1 (mod q)` that makes the window start arbitrary, which is why the window
condition is exactly the residue-level condition there.

## 3. Bigfoot

The kickoff asked for the smallest `d` the condition gives on the reachable set.  Three answers,
by certificate class:

| certificate | smallest `d` | declaration |
|---|---|---|
| plain cyclic window | 14 | `bigfoot_window` [Lean] |
| window from reachable residues, trap = `{14, 17, 23}` | 13 | `bigfoot_resWindow` [Lean] (other traps `⊆ {14,17,23}`: 13 or worse, [computed]) |
| residue drift certificate (potential) | 7 | `bigfoot_drift` [Lean]; `≤ 6` impossible [computed] |

The drift certificate was found by value iteration on the residue game (state `X mod 24`,
adversary picks `t = ⌊X/24⌋ mod 3`, we pick `c ≤ d`, payoff `w`), and checked in Lean by
`decide +kernel`.  Its game value is `−1/3` at `d = 7`, `0` at `d = 1..6`.

**Lifting (stretch, Lean).**  The residue game is pessimistic for a structural reason: the image
`32⌊X/24⌋ + h[X mod 24]` mod `24` depends on `⌊X/24⌋` only mod `3`, because `32 ≡ 0 (mod 8)`.
So a steering that knows `X mod 72` knows the next residue mod `24` exactly; only the following
base-3 digit is adversarial.  In general, state `X mod Q` with `Q = 8·3^j` needs the check over
`X mod 3Q` only (`Q ∣ 32·(3Q/24) = 4Q`), which is the general-period gate (row 18).

| certificate | smallest `d` | declaration |
|---|---|---|
| lifted, `X mod 72` | 2 | `bigfoot_halting_member_two` [Lean] |
| lifted, `X mod 1944` | 1 | `bigfoot_halting_member_one` [Lean] |

Defect `0` is the cryptid, so `d = 1` closes the ladder `14 → 13 → 7 → 2 → 1`: in the `X`
coordinate, arguments blind to a single unit of rounding (`F_{L,1}`, every `L ≥ 1`) cannot prove
Bigfoot non-halting, near the cryptid.  Both certificates were found by `energy.js` and
re-checked on all `X mod 24Q` by `checkbf.py`; Lean checks them by `decide +kernel` (`216`
residues, instant; `5832` residues, about a minute).

## 4. Sharpness (target 4)

**Antihydra** (`d_min = 1`): trivially sharp; the `d = 0` family is the single map.

**#218** (`d_min = 2` for the window): **not sharp [Lean: `Cert218.hydra218_halting_dense_one`]**.  The window fails
at `d = 1` (`hydra218_window`), and the residue game confirms it: with `t` adversarial the
adversary can always present the window `{0, 1}` (walk `+3, +1`).  But the steering may look
further ahead.  In `u = x + 3` coordinates the map is `u ↦ u + ⌊u/3⌋ + c`, so the low `k` base-3
digits of the image depend on the low `k + 1` digits of `u`.  Make the state `u mod 3^k` and let
the adversary choose digit `k`.  This game is still a sound sufficient condition, by the general
gate (row 3) with `Trap = True`, `Φ x = φ(x mod 3^k)`.  Its value falls through zero at
`k = 10` (row 15), and an integer certificate exists there: `m = 14`, `φ ≤ 135`.

Heuristic for the limit: the greedy strategy keeps the residue in `{1, 2}` and lands on `2` unless
`r + t ≡ 0 (mod 3)`; with `t` equidistributed that gives mean `−1/3` per step.  The lifted game
values `−0.074, −0.11` at `k = 10, 11` are moving towards it.

**The Lean proof.**  The generic lifted gate `Sys.halting_dense_of_modCert` (state `x mod Q`,
check over `x mod qQ`; the image mod `Q` depends only on `x mod qQ`, `Sys.img_shift`) reduces the
claim to a finite check.  `Collatz/HydraFoils/Cert218Data.lean` packs `φ` (32 entries of 8 bits
per leaf, a balanced tree navigated by the recursor) and defines the Boolean checker `chk`;
`Cert218ChunkA/B/C` run `decide +kernel` on 18 chunks of `10^4` residues (about 2 minutes, about
1.5 GB per module); `Cert218.lean` bridges `chk` to the gate.  `sim/hydra_foils/gen218.py`
re-checks the certificate in Python and regenerates the data module.

So the ladder for #218 is: window `d = 2`, lookahead `d = 1`, and `d = 0` is the cryptid itself.
Defect `1` is the least defect at which the gate applies at all, and it applies.

*Build notes (kernel cost).*  `==` on `ℕ` reduces through `Nat.decEq`; `Nat.beq` and raw
`Nat.mod/div/shiftRight` cut the kernel's time and memory by about 2x.  A 59 KB single literal
table with `>>>` lookups was far slower and was OOM-killed on the full range.

## 5. Computation

Scripts in `sim/hydra_foils/` (python3 / node, no dependencies):
- `bf.py`: Bigfoot `hydraIterate 32 24` from `(10, 2)`, residues of the first 20000 steps.
- `win.py`: window `d` per trap subset of `{14, 17, 23}`, entries all / reachable.
- `cert.py`: residue energy game, potential by value iteration with cap `q(m max|w| + 1) + 1`.
- `g.js`: lifted mean-payoff game value (`u mod q^k`, adversarial digit), `V_n / n`, `n = 6000`.
- `energy.js`: lifted energy game; certificate existence and size.
- `checkbf.py`: re-check a Bigfoot lifted certificate on all `X mod 24Q`, emit the packed table.

Control: the same residue solver gives value `+1` at `d = 0` for Bigfoot (the adversarial
`t` makes the walk `+1`), and `+1` for #218 at `d = 1`, `k = 1` (the window failure, which is a
Lean theorem).  Both match.

## 6. Not claimed

- Nothing here bears on whether any cryptid halts.  The gate says rounding-blind arguments
  (inputs shared by all of `F_{L,d}`) cannot prove non-halting.  For Bigfoot that means
  arguments blind to defect-`1` roundings (`bigfoot_halting_member_one`).
- The Bigfoot theorems (defects 7, 2, 1) are existence near the cryptid (`σ₀ = 0`), not density
  at arbitrary `σ₀`:
  the entry predicate `X ≢ 0 (mod 4)` is only known along the zero member's orbit.
- For #218 at `d = 1`, the Lean certificate shows density; the game values of row 17 are not in Lean.
- Minimality claims are about certificate classes.  `¬ Window 1` (#218), `¬ Window 13`
  (Bigfoot) and `¬ ResDrain 12` (Bigfoot, negative trap) are Lean; "no drift certificate at
  `d ≤ 6`" is computed.  None says a defect-`d` member cannot halt.
- Non-halting members of the generic family: not studied (T2's `AllNonhaltingMember` stays the
  record for Antihydra).
- Prior work: not searched this lap (no egress); T2's search found nothing on rounding-choice
  foils.
